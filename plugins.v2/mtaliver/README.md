# 馒头保活助手（mtaliver）

首次使用账号密码和手动邮箱验证码登录，保存浏览器 Cookie、localStorage、sessionStorage，以后每天打开站点首页。容器重启后可从插件数据恢复会话；修改账号或站点地址后，需要重新验证。

## 安装和首次验证

1. 在 MoviePilot 插件市场添加本仓库 `https://github.com/tmzg0000/MoviePilot-Plugins`，刷新后安装「馒头保活助手」。
2. 在「馒头保活助手 - 插件配置」填写 M-Team **账号、密码、绑定邮箱**，以及可选的 API Key。
3. 直接点击 **获取验证码**，等待同一配置页显示发送结果。按钮会保存账号、邮箱等设置，密码仅在本次请求中临时使用，不会保存；不需要先点击底部「保存」。
4. 收到邮件后填入 6 位验证码，点击 **登录**。等待同一页显示登录结果，验证码提交后自动清空。不要重复点击获取验证码，以免旧验证码失效。
5. 开启「启用定时刷新」并保存（也可以先开启，再点击上述按钮自动保存并生效）。默认 Cron 为 `35 1,9,21 * * *`，按 MoviePilot 时区每天 01:35、09:35、21:35 检查是否需要保活；默认同日成功后跳过。**立即刷新**可强制复用会话访问一次。

获取验证码、登录和立即刷新按钮直接执行，操作期间按钮显示加载状态并禁止重复点击。账号信息通过 MoviePilot 前端自带的认证 API 客户端以 POST 请求正文提交，不放入 URL。需要支持 `window.MoviePilotAPI` 和动态表单 `onClick` 的 MoviePilot V2 前端；不支持时会在配置页提示更新宿主。旧版本的「勾选后保存」配置仍可兼容，但新界面不再显示这些开关。

按钮返回“已登录并保存会话”代表网页身份验证成功；活动时间未更新时会另附校验提示，不会把验证码登录误报为失败。定时刷新仍按活动校验设置记录结果。

插件不会定时发送验证码。会话失效时会报告失败，开启通知后提示重新验证。站点若要求再次验证，就仍需手工填码，无法保证永久只验证一次。

## 浏览器和校验

需要 MoviePilot 本地 Playwright 浏览器及 `PlaywrightHelper.action()`；容器必须能连接站点与 `static.m-team.cc`。站点页面结构改变、安全验证或网络限制可能导致登录失败。没有浏览器依赖时插件会给出失败原因，不会自动安装环境。

可选填写 API Key，或自动使用 MoviePilot 站点管理的 M-Team API Key。默认开启「最近动向」校验：浏览器须收到有效账号响应，同时最近动向须比执行前更新且处于配置时间窗口内。有 Key 但统计接口失败时，会报告无法确认；关闭校验或没有 Key 时，仅能证明网页会话有效。API 统计请求不作为网页访问成功的依据，也不能把浏览器失败改为成功。

**复用会话访问是否满足 M-Team 当前保号规则，需要部署后检查「最近浏览/最近登录」及站点规则。**上游描述其环境中复用会话没有刷新活动时间；本版本不能承诺每日访问就能重置删号计时。未使用真实账号进行线上登录测试。

## 凭据存储

密码框默认留空、遮挡输入且不回填旧密码。密码输入不绑定配置模型，底部「保存」也不会保存密码；获取验证码和登录时仅将临时密码放在请求正文中，后端处理后清空，登录提交后前端输入框也清空。重新打开配置页需重新输入密码才能再次认证；后续定时刷新只使用会话，无需密码。升级会从活动插件配置中删除旧明文密码，并迁移匹配的已有会话；旧的外部备份不会被修改。

账号、邮箱及 API Key 仍按 MoviePilot 插件配置保存；浏览器会话在插件数据 `browser_state` 中保存，包含登录凭据。不要分享配置/数据备份。验证码不写入日志、历史或结果页；会话不在配置表单或结果页显示。卸载时可选择删除插件配置和数据。

本地模拟测试：`python3 -m unittest discover -s tests/mtaliver -v`。
