## 升级与登录

直接更新原来的「GlaDOS 签到助手」，无需卸载。旧的签到历史保留；旧版 Cookie、cURL 和浏览器指纹不迁移为新会话，首次升级后需要重新登录。

1. 在插件配置中填写 GLaDOS 登录邮箱、实际登录域名（例如 `https://glados.space`）及所需代理配置。
2. 将「本次保存执行」设为「发送验证码」，保存。操作在后台执行，稍后重新打开配置或数据页查看结果并查收邮件。
3. 收到验证码后重新打开配置，填写验证码，将「本次保存执行」设为「验证码登录」，保存。不要仍选「发送验证码」。
4. 稍后重新打开配置或数据页，确认登录成功。启用插件并设置 Cron；也可以勾选「保存后立即签到一次」。登录和立即签到同时选择时，仅在登录成功后签到。
5. 平时保持「本次保存执行」为「只保存设置」。需要退出时选择「退出登录」后保存。

一次性操作和验证码在插件初始化时立即从配置中清除，后台任务仅短暂持有验证码，不将其写入插件数据或调度参数。登录结果在配置页和数据页显示。关闭通知不影响显示登录结果。

## 会话与设备

- 发码、登录、签到和账号查询由 MoviePilot 服务器完成，复用同一套持久化设备身份和 User-Agent。无需复制浏览器 Cookie 或执行指纹提取代码。
- 登录后使用 `/api/user/status` 验证账号与所填邮箱一致，再保存会话。只有跳转或匿名 Cookie 不会被当作登录成功。
- 会话和设备身份保存在原插件的数据中，重启和普通配置保存后继续使用；接收服务端轮换的 Cookie 并回写。
- 更换域名或设备平台后需重新登录；不同域名不复用会话。账号在其他设备重新登录仍可能触发服务端设备校验，遇到提示请在本插件重新登录。
- 返回 `code=-2` 时清除失效会话并提示重新登录，数据页不把原缓存点数、剩余天数当成实时信息。历史记录仍保留。
- 遇到人机验证、Cloudflare 拦截或限流会显示提示，本插件不自动完成人机验证。

## 与上游的区别

保留上游 4.0.5 的签到、定时任务、失败分类通知及去重、积分兑换、历史同步和会话轮换逻辑。用 V2/V3 原生表单和数据页替代 Vue UI，移除仅供 Vue 使用的自定义 API；保留宿主认证的配置保存流程。修复代理失败后直连兜底分支，增加登录后的账号验证、按域名隔离会话，并隐藏未登录状态下的旧余额。

V2 与 V3 目录同步为本仓库的 3.6.2，后端和原生页面保持一致，并兼容旧版 app.core 与新版 app.sdk 导入路径。3.6.2 是本仓库独立版本号，后端基础来自上游 4.0.5。
