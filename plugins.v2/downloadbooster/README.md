# 刷下载 1.0.3

支持 MoviePilot V2 / V3，复用 MP 配置的一个 qBittorrent 或 Transmission 下载器。多个下载器请使用 MP 插件分身，各分身使用独立配置、进度和调度任务。

## 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用插件 | 关闭 | 保存启用后约3秒执行首次检查，之后按检查间隔运行 |
| MP下载器 | 必选 | 单选，支持 qBittorrent / Transmission（标签功能要求 TR 3+） |
| 种子文件夹 | 必填 | MP容器内可读目录，仅扫描本层 `.torrent`，相同 info hash 去重 |
| 数据保存目录 | 必填 | 下载器内的专用绝对路径，例如 `/downloads/刷下载`；不要求MP能访问 |
| 目标下载量 | 100 GiB | 1G = 1024³字节，只统计插件任务的实际下载计数增量，包含未完成任务 |
| 任务标签 | 刷下载 | 单一标签，不含英文逗号；只添加此标签，不增加其他身份标签 |
| 下载完成后保留做种时间 | 15分钟 | 从下载器报告的完成时间计算；无有效完成时间则从首次观察到完成起算 |
| 确认删除后重新添加间隔 | 15分钟 | 删除成功且确认任务消失后起算；后续检查发现消失则从该次检查起算 |
| 检查间隔 | 10分钟 | 最少1分钟，条件满足后在下一次检查执行 |
| 日志保留天数 | 5天 | 大于等于1的整数，按实际经过的24小时计算，超期记录自动删除 |
| 达到目标后的处理 | 完成下载、做种后清理 | 可改为下一次检查达标时立即删除本插件任务及数据 |
| 重置统计并开始新一轮 | 关闭 | 保存后执行一次；保留已有任务和等待时间，只重置累计量与达标状态 |

## 运行流程

1. 同一检查轮次中提交目录中所有有效种子，让下载器同时下载；不限制下载器自身的队列和并发设置。新发现的源种子也会在后续检查中添加。
2. 每个种子、每轮下载使用数据保存目录内的随机专用子目录，防止多个种子同名覆盖或重加后复用上轮文件。子目录形如 `mp-downloadbooster-<随机ID>`，源 `.torrent` 文件一直保留。
3. 记录本插件任务的实际下载字节增量。重启MP、保存设置、关闭再开启均继续累计，不重复计算已经保存的计数。
4. 下载完成后等待配置时间，删除任务及数据。先持久化删除意图；失败则下次重试。确认任务已消失后开始等待重新添加间隔，到时再次提交。
5. 累计量达到目标后锁定达标状态，不再添加任何新任务。默认让现有任务完成下载、保留做种至时间满足后删除；全部清理后显示“已完成”。提高目标值不会自动解锁，请使用重置开关开启新一轮。
6. 重置时以当前下载器计数作为新基线，已有任务继续原有生命周期。勾选启用则继续自动循环；插件关闭时重置只清零，不启动下载。

## 检查记录

每次实际执行检查都追加一条持久化记录，即使没有新增／删除任务，也不会覆盖上一条。下载器连接失败等检查异常也会记录。页面按新到旧在可滚动表格内逐条展示检查时间（MP时区）、状态、累计下载量、本次提交添加数量、确认移除数量、管理中任务数和说明。表格上方显示实际记录总数，固定表头，支持滚动查看全部保留记录。配置保存后的首次检查也会记录；因关闭插件或上一轮尚未结束而跳过的调度不算一次检查。

默认保留最近5天，每次写入记录或查看运行页时删除超过保留天数的日志；修改保留天数后在下次写入或查看时生效。关闭插件且不查看运行页期间不会单独启动清理任务。重启MP和重置下载量都保留尚未过期的检查日志。该设置针对本插件运行页记录，不修改MP全局日志。旧版只存了最新状态，无法还原旧版过去每次检查的历史。

## 任务归属及异常处理

- 不含配置标签的已有同哈希任务直接跳过，不计入累计量，也不接管或删除。
- 配置标签是唯一管理依据：下载器中所有带此标签的任务，无论有无内部记录、保存到哪个目录，都会纳入统计及到时删除任务和数据。首次纳入时将任务当前累计下载量计入统计，之后只累加增量；移除此标签则停止管理该任务。
- 分身使用运行时插件类名隔离调度，进度使用MP分身自身的数据空间。分身选择同一下载器且源种子相同时，已有哈希仍会跳过。
- 添加前记录意图，添加响应不明确时按配置标签恢复；不存在时重试添加。查询失败绝不会被当作任务已删除。升级后自动移除有历史记录的任务上由旧版添加的随机长标签，保留其他标签和累计进度。
- 种子目录丢失、个别种子无效不妨碍已有任务的清理；恢复目录后可继续添加。支持传统 BT v1 及 hybrid 种子，纯 BT v2 种子跳过并提示；这里的 BT 版本与 MoviePilot V2/V3 无关。
- 下载器绑定随进度保存。更换下载器前需让原下载器中的插件任务清理完毕，再选择新下载器并勾选重置；不会把原任务记录用于另一个下载器。
- 关闭插件会暂停检查管理，下载器已有任务继续运行。重新启用后恢复管理。不要在有任务时直接删除插件进度数据。

## 统计和时间边界

默认10分钟检查、15分钟做种／重加间隔，满足条件后才在检查时操作，实际等待可能接近25分钟。做种时间表示下载完成后的保留时长，不扣除暂停、下载器离线时间，也不表示持续有上传流量。

累计量使用 qBittorrent `downloaded` / Transmission `downloadedEver`，不包含其他任务，不按种子标称大小累加，不等同于站点最终记录的下载量。外部在两次检查之间删除任务时，最后一次未观察到的下载增量无法补回。若外部清零计数，插件保留原累计值，从新的计数继续统计。

检查间隔内产生的下载量和默认收尾期间的下载量都可能使最终值超过目标；“立即删除”也是检查发现达标时执行。下载器自身队列、暂停、限速、分享率停止规则仍生效；未完成任务不会被默认收尾策略提前删除。请按磁盘空间及站点规则设置并发、目标和做种保留时间。

## 验证

本地离线测试覆盖循环边界、重启恢复、实际增量统计、默认／立即收尾、删除失败及确认、无标签任务隔离、同标签已有任务接管、旧标签迁移、重置基线、双版本入口与原生客户端字段转换。尚未在真实 MP 容器与下载器环境进行端到端验证。
